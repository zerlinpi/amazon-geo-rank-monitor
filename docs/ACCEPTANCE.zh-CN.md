## 本轮复现并修正的数据准确性问题

1. **搜索范围越界**：配置前 100 个自然结果，实际返回第 101 个时，旧匹配逻辑仍标记为找到。现在在自然结果序列的深度边界截断，广告位置仍单独记录。
2. **采集不足被当作完成**：旧 Managed 适配器按每页 48 条估算；每页实际 16 条时，前 100 名只取到 48 条就返回。现在按实际自然结果数继续请求，不重复请求已完成页，并限制最多 20 页。
3. **分页与解析错误导致错排**：现在按页号排序，检查缺页和重复页，支持提供商的 `pages` 总页数字段并拒绝矛盾的分页信息。仅接受明确解析成功的响应；解析失败、部分解析及无效自然商品记录明确报错，避免假报“未找到”、污染缓存和错误扣除应用 credits。保留提供商文档支持的广告 `rel_pos` 字段。
4. **Strict 截断误报**：到达浏览器扫描页数上限但仍有下一页时，返回明确错误，不把未完成的扫描当作商品未找到。
5. **竞品口径不一致**：竞品自然/广告排名分别按各自序列计算，与排名监控保持一致；不再把混排位置直接作为自然名次。
6. **旧缓存继续污染结果**：缓存标识包含解析版本；升级后重新采集，不复用旧解析规则的缓存。

上述异常先由回归用例复现，再修改生产代码。没有新增业务模块或改写历史数据。提供商接口字段及解析状态参考 [Oxylabs Amazon Search 官方文档](https://developers.oxylabs.io/products/web-scraper-api/targets/e-commerce/amazon/search.md)和[响应状态码文档](https://developers.oxylabs.io/products/web-scraper-api/response-codes.md)。

### 升级后的数据和成本边界

- 历史错误排名和竞品记录不会自动重写。重新采集建立可靠基准；修正前后的差异可能来自算法口径变化，不应直接解释为真实排名波动。
- 更深的搜索可能需要更多提供商页面请求；最多 20 页。到达限制仍未覆盖目标深度且未确认搜索结束时，本次 GEO 失败，应降低深度或检查上游，不应认定 ASIN 掉出排名。
- `prepaid` 模式的应用 credit 费率按 GEO 探针规则计算；`free` 模式不扣应用 credits。两者都不是提供商实际按页/请求收费的报价，失败调用也可能已产生提供商费用。上线前核对真实账户的价格、额度和调用记录。
- 缓存失效后的首次运行会重新访问上游。已有订阅、告警、调度和账本不会因此被清空。

## 达到可日常使用还需要完成的验收

### 1. 建立可访问的运行环境

按 [部署手册](DEPLOYMENT.md) 配置 HTTPS 域名、数据库、Redis、固定加密密钥、API、Worker 和 Scheduler。确认登录、退出、刷新和手机访问正常；健康检查不能替代后面的采集验收。

### 2. 打通首次真实监控

配置 Managed 提供商账户，保持 `BILLING_MODE=free` 即可在零应用余额下运行。若选择 `prepaid`，由服务器管理员使用 `agrm-credits` 发放额度，或配置有效的信用包价格及 Stripe Checkout/webhook 后充值。**提供商余额与应用 credits 是两套账；调账不会给 Oxylabs 充值，免费模式也不免除提供商费用。** 人工调整应使用有审计账本的命令，不直接修改数据库；线上充值需验证签名 webhook 到账。

用一个实际关键词、一个目标 ASIN、一个配送 ZIP、较小搜索深度执行一次手动监控，核对：

- 实际访问了目标站点与配送地区；Managed 结果没有冒充已核验出口 IP。
- 页号连续，已扫描自然结果数量覆盖目标深度，或确认已经到达可用搜索末页。
- 自然排名、广告排名和未找到状态可回溯至这一轮采集结果；上游错误显示为错误。
- Worker 完成任务，结果落库，页面刷新后仍能打开同一轮记录；免费模式无新扣费/预留，或 prepaid 模式额度预留/结算正确。

未配置的 Strict 可保持关闭。只有需要严格地理核验时，才配置住宅代理并单独验证出口 IP、配送 ZIP 和成本，不能用 Managed 成功代替 Strict 验收。

### 3. 验证持续运行与通知

在有明确调用预算的测试 Workspace 中运行完整调度周期，确认按时产生结果。验证一次 Worker 重启后的任务恢复、一次上游失败后的可见状态、一次 SMTP 实际收件，以及一次隔离环境中的备份恢复。报告和告警要检查收件箱与 delivery history，不能只看发送接口返回成功。

根据实际监控规模记录任务延迟、API 响应、错误率、资源占用和上游成本，完成持续观察后再开放日常使用。本记录没有声称已经完成长稳测试。

### 4. 如仍要求 Windows `.exe`

当前交付方式是服务器部署加浏览器访问。签名 `.exe` 需要另行实现桌面客户端、安装器、Windows 测试与合法签名身份。详细边界见 [Windows 发布说明](WINDOWS_RELEASE.md)。现有 Web CI 不能作为桌面程序验收证据。
